# learning_objectives 与同类 harness 比较

## 0. 结论先讲

`learning_objectives` 在控制面这一类里，属于**设计最完整、也最容易养肥的标本**。

- 相对「只写 AGENTS.md / CLAUDE.md / `.cursor/rules`」：它真正把 Guides 和 Sensors 做成了系统。
- 相对 ECC、superpowers 这类开源通用 harness：它更懂多仓业务、停止点、环境/DB 边界；开源方案更懂「少仪式、能量化、能衰减」。
- 相对它自己写的目标（约 100 行 AGENTS、小硬核）：**机制方向对，工程化收敛没跟上**。这不是「还没做完」，而是「做成了之后开始和业务抢资源」。

**要不要调整这份示例？** 学习阶段不要去改 `learning_objectives`。要调整的是**你怎么学、以及你自己那份 v0 抄什么**。他们内部已经把目标写成「小硬核 + 大软壳」；你自建时直接从那个目标起步，不要从它当前的 38 个 gate 起步。

## 3. 相对同类，它强在哪

### 3.1 把「停止」做成一等公民

轻量约定只会写「请先确认」。superpowers 强调 plan 和 verification。这份示例把停止点分成三类（口径不清 / 边界不安全 / 证据不足），并且用 `confidence-gate`、`assumption-leak-gate`、`business-code-start-gate` 去挡。

`[FACT] / [ASSUMP] / [QUESTION]` 是它最值得抄的机制。开源 harness 很少把「没确认的业务规则不得进代码」做成硬门。

### 3.2 控制面和业务仓分离

ECC / superpowers 默认假设「一个 repo 就是工作区」。SFA 是 10 个仓。`repo-registry` + `config/repos.local.sh` + 禁止把业务代码拷进控制面，这是企业场景下开源方案做不到的。

### 3.3 角色权限先于智能

Orchestrator 可写、Explorer/Reviewer 只读、Test Agent 不能宣称实现完成、implementation agent 默认 candidate。superpowers 也有只读 reviewer、不信任 implementer report；这份示例把这套嵌进了多仓和契约并行。

### 3.4 薄适配，不绑死一个 runtime

hooks 只做 adapter，逻辑进 `harness-sensor-runner.sh`。相对「只为 Claude Code 写一套」或「只为 Cursor 写 `.mdc`」，这是正确的工程判断。

### 3.5 有诚实的自我诊断

`docs/harness-diagnosis-and-remediation.md` 和 2026-07-02 使用期诊断，把「仪式过载、拉式门禁、规则不跟随业务仓、度量无数据」写清楚了。很多 harness 只有宣传文档。**学它的时候，诊断文档的价值不低于 AGENTS.md。**

## 4. 相对同类，它弱在哪

这些弱项，他们自己已经诊断过。下面用「同类做得更好的地方」来对照。

### 4.1 仪式过载（对 superpowers / 轻量约定完败）

抽样真实业务 change 要 10–19 个 Markdown。`skill-usage.md` 把能力路由管成强制台账。AGENTS 目标是约 100 行目录，实际已经是硬规则百科。

superpowers 的强项正好是：**阶段少、计划具体、完成必须有新证据**，而不是每一步再产一个 gate 文件。

影响：维护 harness 开始和交付业务抢资源。诊断里写过，`changes/` 一度有约 64% 是 harness 自身改造。

### 4.2 强制力是拉式的（对 ECC / Claude Code permissions 完败）

关键 gate 要靠 Agent **自觉去跑**。hooks 只拦部分危险 shell；`afterFileEdit` 在没设 `SFA_CHANGE_SPEC` 时直接放行；SessionStart 在 Cursor/Codex 上未接线。

Anthropic / ECC 的原则是：权限和 hook 是工具层强制，不是模型记得。这份示例**书面上同意这条，运行时没做到**。结果就是使用期问题 #2：没确认技术方案也能改代码。

另外：`afterFileEdit` / `PostToolUse` 不能撤销已写盘的文件。把「硬拦截」写在 post-edit 上，是高估了 hook。物理阻断只能放在 `beforeShellExecution` 对 `git add/commit/push`，再加 stage gate。

### 4.3 规则不跟随业务仓 workspace

规则和 hooks 住在控制面仓。人在 `mapSystem` 里开 Cursor，约束一条都不生效。这是多仓控制面的结构性漏洞。ECC 可以假定当前仓即工作区；这份示例选了分离架构，却没有把薄 stub 稳定分发到业务仓。

### 4.4 有度量管道，没有度量闭环（对 ECC 完败）

ECC 有 audit 打分、skill 7d/30d 成功率、behavior compliance eval。这份示例建了 telemetry / weekly audit / behavior eval，但真实事件很少，behavior eval 一度是「检查规则文案」的纸面 eval。gate 没有 catch / false-positive 数据，就无法退役，于是只增不减。

他们自己的目标形态已经写了：**小硬核 + 大软壳 + 衰减反力 + 结果耦合**。当前实现仍是「gate 作为默认机制」。

### 4.5 危险命令黑名单可绕过

诊断记录：`git push -f`、`rm -Rf` 这类变体可能放行。L3「硬核」强度被高估。开源 hook 套件通常会把安全拦截做成更保守的模式匹配或 allowlist。

### 4.6 领域耦合过深，当教材会误导

飞书同步、SFA Vue2 class 名、Java Swagger VO、个人绝对路径的 lark skill（`skills-routing.md` 里出现过 `/Users/00555733/...`）——这些是这份 harness 的产品，不是 harness 的原理。如果当「标准 harness 长这样」来抄，会把 SFA 一起抄回家。

## 5. 需要做什么调整？

分三件事，不要混：

### 5.1 不要改 `learning_objectives`

它是别人的标本。学习阶段去「帮它减负」会把学习变成另一场 harness 改造。他们自己的整改清单已经在诊断文档里。

### 5.2 调整怎么学（建议立刻采用）

1. **AGENTS + 工作流文档 + 诊断文档，三份一起读。** 只读 AGENTS 会以为这是理想态；诊断才是它运行后的真相。
2. **把「机制」和「SFA 积木」分开记。** 机制：停止点、FACT/ASSUMP、薄适配、独立 Reviewer。积木：38 个 gate、飞书、Vue2 细则、skill-usage 台账。
3. **学习计划 Week 3 不要扫完全部门禁。** 继续只解剖 L3 那几个；L1 台账类当作反面教材。
4. **加一课：读 2026-06 诊断的「小硬核 + 大软壳」和 2026-07 的三个根因（拉式、不跟随 workspace、度量无进料）。** 这比再读 10 个模板更重要。

### 5.3 你自己那份 harness 的调整（相对「原样复制」）

直接从他们的**目标形态**起步，而不是从当前仓库起步：

| 抄 | 改 | 丢掉 |
|---|---|---|
| 五层模型、三类停止点 | gate 从第一天就是推式：未过 code-start 不能 `git commit` 业务仓 | 38 个 gate 全量 |
| FACT / ASSUMP / QUESTION | AGENTS 真的当目录，细节进 docs | `skill-usage.md` 硬门 |
| 一次变更一个 `changes/<id>/` | 业务仓放薄 AGENTS stub + hook 指针，规则跟 workspace 走 | 每个需求 10+ 文档 |
| 薄 adapter，逻辑不复制进 Cursor 配置 | 只保留 4–6 个 L3；L1 用状态卡字段而不是新脚本 | 飞书同步、SFA UI class、Swagger 细则（除非你就是那套业务） |
| 只读 Reviewer，Main 不能自评完成 | 有数据之前不新增 gate；加规则前先有失败样本 | 未接线的 SessionStart 空架构 |
| Optional Packs / Tier S 可以很小 | hook 安全拦截用 allowlist 或保守匹配，不要自欺的黑名单 | 把 post-edit 当成物理阻断 |

v0 建议仍是上一份计划的 Week 7–8：短 AGENTS、1 个 lane、tier-s 三件套（spec / status / evidence）、4 个 L3、1 个只读 Reviewer。另外加一条他们栽过的：**这 4 个 L3 至少有 1–2 个要挂到 hook 上推式触发，不能全靠模型去跑脚本。**

## 6. 一句话定位（方便以后回看）

`learning_objectives` = 企业级控制面 harness 的**高完成度标本**，也是「规则和 gate 只增不减」的**活体反例**。

学它的骨架，读它的诊断，不要克隆它的体重。
