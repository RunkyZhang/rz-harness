## 要解决什么

一次需求里，信息来源混在一起：PRD 写了的、代码里已经是这样的、你口头说的、模型自己脑补的。不拆开的话，模型会把后两种直接写进接口和页面。

所以规定：

- 能进实现的，必须是带着来源的事实
- 猜的，先标出来，确认前不能变成代码
- 必须你拍板的，写成问题，没答就停

聊天记录不是事实源。改完之后，以 `spec.md` 里的标签为准。

---

## 三个词分别是什么

**`[FACT]` 事实**  
有出处才能写。出处只能是：PRD、你确认过、现有代码、已冻结契约、线上已有行为。  
没出处的业务规则、字段、状态、权限、错误码、默认值、回滚规则，**不是事实**，哪怕模型写得很像。

**`[ASSUMP]` 假设**  
模型推断，但还没人确认。常见是「大概复用现有列表页」「错误码应该跟同类接口一样」「空列表大概返回 `[]`」。  
限制：确认或删掉之前，**不得进入实现**。不是「先按这个写，以后再改」。

**`[QUESTION]` 问题**  
必须你决定，Agent 不能替你选。例如做哪个仓、空态展示什么、有没有权限位、要不要动表。  
限制：阻塞项没答清，**不得写业务代码**。

判断口诀：有出处 → FACT；我猜的 → ASSUMP；必须你拍板 → QUESTION。拿不准时写 QUESTION，不要先写成 FACT。

## 在流程里怎么走

建包时模板里几乎全是 `[QUESTION]`，那是空壳，不是已经问过你了。

典型一轮：

1. 主 Agent（可让 Explorer 只读供料）读 PRD / 代码，往 spec 里填三标签。
2. 能从 PRD 或代码钉死的，直接写成 `[FACT]` 并写来源。
3. 猜的写成 `[ASSUMP]`。
4. 必须你决定的写成阻塞 `[QUESTION]`。
5. **停**，在对话里问你。你答完后，由主 Agent 把那一行改成带着来源的 `[FACT]`（或确认后的 ASSUMP 也改成 FACT）。你不用自己改 YAML。
6. 再跑 `confidence-gate.sh`。阻塞 QUESTION 还在，gate 失败，不能开工。

所以停止点 1「Spec 三标签」= 拍板 + gate。口头「ok」不算过；spec 里标签改完、gate 过了才算。

## 改标签时一个机械细节

`confidence-gate` 是扫文件里还剩不剩 `[QUESTION]` 这串字。你答完之后如果写成：

```markdown
- [QUESTION] 空列表返回什么？
- [FACT] 空列表返回 `[]`（用户确认）
```

gate **仍然失败**，因为 QUESTION 那行还在。正确是原地改掉：

```markdown
- [FACT] 空列表返回 `[]`（来源：用户 2026-09-13 对话确认）
```

没有假设时不能删掉 ASSUMP 这一节。gate 要求三种标签都出现，空的写：

```markdown
- [ASSUMP] None.
```

非阻塞问题（不影响这次实不实现）放到：

```yaml
non_blocking_questions:
  - [QUESTION] 文案以后是否要产品再过一眼？
```

默认情况下，这里的 QUESTION **不拦开工**。不确定是不是阻塞时，放在正文里当阻塞项，宁可多问一次。

## 和「假设泄漏」的分工

两道关，查的不是同一件事：

| | 查哪 | 过不了意味着 |
|---|---|---|
| `confidence-gate` | spec 里还剩阻塞 `[QUESTION]` | 问题没答完，不能开工 |
| `assumption-leak-gate` | **业务代码**里出现了 `[ASSUMP]`，或假设里的标识进了 `.java` / `.vue` | 假设漏进实现 |

注意：现在的 `confidence-gate` **不会**因为 spec 里还留着未确认 `[ASSUMP]` 就失败。ASSUMP 主要靠纪律 + 泄漏扫描。流程要求是：要拿这条去写代码，先把它确认成 FACT，或从范围里拿掉。不要依赖「gate 没红就等于假设已经合法」。

## 小例子

PRD 只写了「客户列表增加最近拜访时间」，没写空数据、没写权限。

可以这样拆：

```markdown
- [FACT] 列表要增加「最近拜访时间」列（来源：PRD 第 3 节）
- [FACT] 现有列表接口是 `GET /customer/list`（来源：`CustomerController.java`）
- [ASSUMP] 该字段复用客户详情里已有的 `lastVisitTime`，不新增列
- [QUESTION] 从未拜访时单元格展示「-」还是空？
- [QUESTION] 是否需要新权限点，还是沿用客户列表原权限？
```

你确认「从未拜访展示 `-`，权限沿用原列表」且「复用 `lastVisitTime`」之后：

```markdown
- [FACT] 从未拜访展示 `-`（来源：用户对话确认）
- [FACT] 不新增权限点，沿用客户列表原权限（来源：用户对话确认）
- [FACT] 使用已有字段 `lastVisitTime`，不新增 DB 列（来源：用户确认；代码 `CustomerDO#lastVisitTime`）
```

这时才允许按这些去改接口和页面。若你还没答「展示什么」，主 Agent 不该自己选一种先写上。

## 常见用错

1. 把模型推断标成 FACT，来源写成「根据现有风格」——那是 ASSUMP。
2. QUESTION 你口头答了，spec 没改标签，状态卡却写「已确认」。
3. 把「错误码大概用 40001」写进 Java 注释或代码，spec 里还留着 ASSUMP。
4. 把所有不确定都塞进 `non_blocking_questions`，开工后门禁形同虚设。
5. Explorer 查到的东西直接当 FACT：Explorer 只供料，主 Agent 落 spec 时仍要看来源够不够。

## 和后面关卡的关系

三标签过了，只说明 **这次要做成什么样** 里，阻塞口径已经钉住。不等于方案已确认、不等于可以改业务文件。后面还有技术方案、测试方案、`allowed_paths`、开工门禁。三标签是第一道「别把猜的写进代码」。
