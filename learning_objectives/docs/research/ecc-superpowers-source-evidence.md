## Questions Used For Source Review

| Question | Why It Matters For SFA Harness |
| --- | --- |
| Q1: What failure mode does this mechanism prevent? | Avoid importing generic OSS mechanisms that do not solve SFA's real problems. |
| Q2: Is the mechanism hard-blocking, soft-warning, or measurement-only? | SFA needs "small hard core + large soft shell"; not every rule should be a gate. |
| Q3: What evidence does the mechanism preserve? | Long-term maintainability depends on durable evidence, not chat memory. |
| Q4: Does it support decay, retirement, or effectiveness measurement? | Current SFA diagnosis says the harness lacks metrics and gate retirement. |
| Q5: Does SFA already have a local equivalent? | Prefer strengthening existing control-plane scripts over copying OSS runtime wholesale. |
| Q6: What must not be copied? | SFA has business-specific constraints: Feishu PRD, multi-repo registry, SIT/UAT, DB write boundary, protected configs, and Chinese review docs. |

## Source-Level Conclusions

1. [ECC-SOURCE] ECC's strongest transferable mechanisms are audit dimensions, health trend records, behavior compliance measurement, lifecycle hook contracts, and optional worktree orchestration.
2. [SP-SOURCE] superpowers' strongest transferable mechanisms are strict plan quality, evidence-before-claim, task/file handoffs, durable ledgers, read-only skeptical review, and behavior evals for skill changes.
3. [LOCAL-FACT] SFA already has many of the hard safety mechanisms; the missing part is not "more gates", but evidence-backed governance for when gates should stay hard, become soft, merge, or retire.
4. [AI-INFERENCE] Do not directly import ECC or superpowers as SFA's control plane. SFA's business properties require a local harness model: Feishu PRD, multi-repo registry, environment readiness, DB/write boundaries, protected configs, Test Agent / Reviewer Agent separation, and Chinese review docs.
5. [AI-INFERENCE] The next technical solution should treat OSS mechanisms as design patterns and cite exact evidence IDs from this matrix, not as wholesale dependencies.
